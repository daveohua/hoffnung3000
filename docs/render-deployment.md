# Deploying to Render

This application is deployed as one Docker-based Render Web Service plus a
Render Postgres database. User-uploaded images must be stored in S3: a Render
service filesystem is ephemeral and must not be used for production uploads.

## Before you begin

1. Commit and push `Dockerfile`, `.dockerignore`, and `render.yaml`.
2. Create an S3 bucket if the platform accepts image uploads. Give the IAM user
   only the permissions required for that bucket.
3. Have SMTP and (if enabled) PayPal credentials ready. Do not add them to Git.
4. Choose an initial administrator email address and a strong, unique password.

## Create the services

1. In Render, connect the repository and choose **New > Blueprint**.
2. Select the branch containing `render.yaml`, review the proposed Web Service
   and Postgres instance, then deploy it. The Blueprint uses Render's paid
   `starter` web service and `basic-256mb` Postgres plan in Frankfurt; change
   either in `render.yaml` before confirming if that is not suitable.
3. When Render asks for values declared with `sync: false`, enter only the
   integrations you use. `JWT_SECRET` is generated by Render.

Required production settings:

```text
INITIAL_ADMIN_EMAIL
INITIAL_ADMIN_PASSWORD
SMTP_HOST
SMTP_PORT
SMTP_USER
SMTP_PASS
AWS_REGION
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_BUCKET_NAME
```

PayPal is optional:

```text
PAYPAL_ID
PAYPAL_SECRET
PAYPAL_RETURN_URL=https://<your-domain>/api/auth/signup/paypal/success
PAYPAL_CANCEL_URL=https://<your-domain>/api/auth/signup/paypal/cancel
```

The Blueprint links `DATABASE_URL` to Render Postgres automatically. It also
runs migrations before each deploy and seeds the initial database only once.
The seed uses the initial administrator credentials you provide; it no longer
creates the legacy public `adminadmin` account.

## Finish configuration

1. Open `https://<service>.onrender.com/api/health-check`; it should return
   `ok`.
2. In the application's admin area, change the `baseUrl` configuration from
   the seeded placeholder to the Render URL (or the final custom domain).
3. If using a custom domain, add it in the Render service settings, wait for
   TLS provisioning, then update `baseUrl` and the PayPal callback URLs.
4. Confirm that uploads reach S3 and that outgoing mail works before sharing
   the public URL.

## Operations

Render uses the Dockerfile's `CMD` to start the app. The app honors Render's
`PORT` environment variable, and Render monitors `/api/health-check` during
deploys. Review the deploy log after every change; a failed migration prevents
the new version from going live.
